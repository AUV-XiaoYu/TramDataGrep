## 二、任务详情

### T0 — Git 初始化 + 分支流程（最先做，阻塞其他）

**为什么先做**：现在项目不是 git 仓库，没有版本控制，一切改动无法汇总。

**步骤**：
1. `git init`，写好 `.gitignore`（**必须忽略** `venv/`、`__pycache__/`、`*.pyc`、`instance/users.db`、`instance/real_data.db`）。
2. 首次提交作为基线。
3. 建远程仓库（推荐内网 Gitea；临时可用共享盘 bare 仓库）。
4. 约定分支流程：每人 `feature/xxx` 分支 → PR → 合并回 main。

**验收**：`git log` 有基线提交；每人能从远程 clone；`.gitignore` 生效（`git status` 不显示 venv/users.db）。

### T1 — 精简界面 + 中文替代英文

**目标**：界面精简，删除"列信息"整块表，英文表名/列名/类型/枚举值全部用中文关键词替代。

**涉及文件**：
- `templates/table.html` — 删除「列信息」卡片（约 198-243 行）；数据预览表头用 `column_label()` 显示中文
- `templates/index.html` — 表名用 `table_label()`；Schema 名（owner）可保留英文或加映射
- `templates/table.html` / `templates/index.html` — 数据类型、枚举值用 `type_label()` / `value_label()`
- `app.py` — `table_preview` 路由里若不再需要 `columns_info` 可去掉（顺带）

**接入方式**：在 `app.py` 里把 labels 函数注册成 Jinja 全局，或在各模板顶部 `{% set ... %}`。推荐前者：

```python
# app.py create_app() 内
from labels import table_label, column_label, type_label, value_label
app.jinja_env.globals.update(
    table_label=table_label, column_label=column_label,
    type_label=type_label, value_label=value_label,
)
```

**验收**：
- [ ] 表详情页不再显示「列信息」表格
- [ ] 表列表显示中文表名（如「每日客流统计」而非 `DAILY_PASSENGER_FLOW`）
- [ ] 数据预览表头显示中文列名
- [ ] 未收录的字段/表仍能正常显示（回退英文，不报错）
- [ ] `DEMO_MODE=1` 下点一遍浏览→预览→下载，全程无异常

### T2 — 隐藏"用户管理/系统信息"页，降级为按钮

**目标**：把导航栏的「用户管理」「系统信息」两个整页入口，降级为按钮点击后弹窗/内嵌显示，减少页面层级。

**涉及文件**：
- `templates/base.html` — 导航栏改为按钮（或小图标），触发 modal
- `templates/admin.html` — 用户管理内容搬进 modal 或内嵌面板
- `templates/diagnostics.html` — 系统信息内容搬进 modal
- `app.py` — 路由 `admin`、`diagnostics` 本身**建议保留**，仅渲染方式变化

**待确认点**（开工前问一句）："按钮显示"是指（a）点按钮弹模态框，还是（b）塞进导航栏下拉菜单？两种都是改 base.html + 两个模板，不影响后端。

**验收**：
- [ ] 导航栏不再直接链接到 `/admin`、`/diagnostics`
- [ ] 管理员点按钮能看到用户管理和系统信息
- [ ] 普通用户看不到这两个按钮（保持权限隔离）
- [ ] 管理员/普通用户权限仍由 `admin_required` 保护（不因隐藏页面而绕过）

### T3 — 默认用某一时间字段筛选

**目标**：进入表详情页时，日期列下拉框默认选中某个时间字段，用户可直接填日期筛选，无需先选列。

**涉及文件**：
- `config.py` — 新增 `DEFAULT_DATE_COLUMN`（默认时间字段名，可环境变量覆盖）
- `app.py` — `table_preview` 路由：用户未手动选日期列时，自动填默认字段
- `templates/table.html` — 日期列下拉框默认选中该字段

**实现要点**：三个后端都已实现 `get_date_columns()`，默认逻辑写成「优先用 `DEFAULT_DATE_COLUMN`，表中没有就退回 `get_date_columns()` 第一项」。

**验收**：
- [ ] 打开含日期列的表，日期列已预选默认字段
- [ ] 填开始/结束日期点查询，筛选结果正确
- [ ] 若某表没有该默认字段，自动退回第一个日期列，不报错
- [ ] 三种模式下表现一致

## 三、协作规则（全员遵守）

1. **一个文件一个 owner**：谁的文件谁改，跨文件改动在 PR 里说明。
2. **小 PR**：一个 PR 只做一件事，尽量 < 200 行。
3. **统一测试基线**：demo_large / demo_real 模式无需 Oracle，每人本地可完整验证；PR 的"完成"= 冒烟命令通过 + 手工点一遍关键流程。
4. **app.py 是冲突重灾区**：路由改动务必协调，其他改动尽量放自己的模块。
5. **只读铁律**：任何改动都不能给 Oracle 后端引入写操作。
